A COMMON QUESTION

Why read payload before ready?

Because waiting for one load before starting the next wastes time. A modern CPU can start independent work while it waits.

  1. 01

    Predict the branch

    While the ready load is still pending, Core R predicts that ready will be non-zero and that the if body will run.

  2. 02

    Overlap the cache requests

    The address of payload is already known, so the CPU starts that load early instead of waiting for ready, then waiting again.

  3. 03

    Retire only when valid

    The early value stays temporary. A bad prediction, exception, or ordering conflict can squash it and retry it before the program is allowed to observe it.

Important: this is not a weak-ordering trick—strong and weak CPUs both speculate. It only works when the later load’s address is independent and already known.

THE POINT

Not “in order” versus “out of order.”

Both machines can speculate, reorder internally, and fly through uncontended memory accesses. A stronger memory model means more outcomes need to be detected and undone when contention exposes them—not that every operation waits its turn.
